# 02-03: Portal smoothing and fade

## Target
New module `tmpmask/smoothing.py` and its tests. `Point` type is in `tmpmask/handtypes.py` (read only).

## Change
```python
Quad = tuple[Point, Point, Point, Point]

class PortalSmoother:
    def __init__(self, alpha: float = 0.5, fade_in_frames: int = 5,
                 fade_out_frames: int = 6, reset_distance: float = 200.0): ...
    def update(self, quad: Quad | None) -> tuple[Quad | None, float]: ...
    def reset(self) -> None: ...
```
Behaviour per `update` call (one call per video frame):
- Quad present, no previous state → state = quad as is; opacity starts fade-in.
- Quad present, previous state exists → per-point EMA: `s = alpha*new + (1-alpha)*s`. If any point jumped more than `reset_distance` px from its smoothed value, snap to the new quad instead (no EMA for that frame).
- Opacity rises by `1/fade_in_frames` per frame with a quad, up to 1.0 (first frame with a quad returns `1/fade_in_frames`).
- Quad `None` → keep returning the last smoothed quad while opacity falls by `1/fade_out_frames` per frame; when it reaches 0 return `(None, 0.0)` and clear state (next quad starts fresh).
- Returned opacity is always within 0..1.
- `reset()` clears everything.

## Constraints
- Pure Python (numpy optional), no time-based logic — frame counting only; deterministic.

## Ownership
`tmpmask/smoothing.py`, `tests/test_smoothing.py`.

## Observable acceptance
Tests: first quad returned unchanged with opacity 0.2 (defaults); EMA midpoint with alpha 0.5; jump > reset_distance snaps; opacity reaches exactly 1.0 after 5 frames and stays; after losing the quad the same quad is returned with decreasing opacity, then `(None, 0.0)` on frame 6; reacquire after that starts at 0.2; `reset()` works.
