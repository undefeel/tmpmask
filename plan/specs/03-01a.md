# 03-01a: App UX, CLI and texts — ideas and drafts

TASK ID for commits and drafts folder: `03-01` (drafts go to `drafts/03-01/`). Topic: `app` → idea document `docs/design/app.md`.

## Target
The finished user-facing application of tmpmask: a Python 3.12 desktop app (OpenCV window) where two hands form a "portal" (thumb and index fingertips of both hands) and a filter is applied inside it. Reference: a TikTok demo of a "Portal de filtros" made with OpenCV + MediaPipe.

Already implemented modules (read them in the repo to get exact APIs; do not change them):
`tmpmask/handtypes.py` (Hand), `tmpmask/tracker.py` (HandTracker, DEFAULT_MODEL_PATH), `tmpmask/portal.py` (portal_quad, render_portal), `tmpmask/smoothing.py` (PortalSmoother), `tmpmask/gestures.py` (PinchTrigger), `tmpmask/filters.py` (FILTER_IDS, get_filter, next_filter_id), `tmpmask/capture.py` (save_screenshot, Recorder).

## Change
Design the remaining parts so a mid-level implementer can build them without questions:
1. **CLI** (`tmpmask/config.py`, argparse): options at least `--camera` (index, default 0), `--width`/`--height` (requested capture size, default 1280x720), `--mirror`/`--no-mirror` (default mirror on), `--filter` (start filter id, default `purple`, choices = FILTER_IDS), `--output-dir` (default `captures`), `--model` (default DEFAULT_MODEL_PATH). Exact option names, types, defaults, validation errors.
2. **Texts** — all Russian user-facing strings live in `tmpmask/texts.toml`, loaded by `tmpmask/texts.py`. Define the TOML structure (tables and keys), how placeholders are written (Python `str.format` names) and the loader API (e.g. `t(key, **kwargs)`; behaviour on missing key). Required texts: window title; Russian name of each of the 8 filters keyed by id (`purple, thermal, invert, gray, ocean, sepia, pixelate, edges`); CLI description and help for every option; console messages: startup hint with controls, filter switched (with name), screenshot saved (path), recording started/stopped (path), camera cannot be opened, camera returned no frame, model file missing (with path and how to fix), exit.
3. **Controls**: keyboard mapping (next/previous filter, digits 1–8 direct choice, screenshot, record toggle, quit with `q` and `Esc`) — only keys reliably reported by `cv2.waitKey` on macOS/Windows/Linux (no arrow keys). Pinch gesture = next filter. Small red recording dot in the corner while recording (no text overlay on the frame).
4. **Main loop** (`tmpmask/app.py`): `run(...)` takes a frame source (iterable of BGR frames), a tracker object with `detect(frame, ts_ms)`, the config, a clock function, and a `display` flag/callback, so it can be tested headless with synthetic frames and a fake tracker; plus `main(argv=None) -> int` that wires real camera (`cv2.VideoCapture`), `HandTracker`, window and keyboard. Per-frame order: read → mirror → detect → pinch trigger → portal_quad → smoother → render_portal → recording dot → record → show → key handling. Exit codes for normal exit and each error. `tmpmask/__main__.py` calls `app.main`.
5. **Edge cases**: one hand / three hands, hands lost, camera unplugged mid-run, model missing, output dir not writable, start filter invalid, recording when closing the window (must finalize the file), window closed by the mouse.
6. **README.md** for people (Russian): what it is, install (Python 3.12 venv commands), run, controls table, options, where captures go, troubleshooting (camera permission on macOS, model missing).
7. **Verification criteria**: concrete checks for the implementer and reviewer, including an automated headless test of `run` and `python -m tmpmask --help`.

Drafts: one file per target — `drafts/03-01/texts.md` (target `tmpmask/texts.toml`, body = the complete TOML) and `drafts/03-01/readme.md` (target `README.md`, body = complete README).
