## Change
Fix exactly these review findings:
1. `tmpmask/app.py` `main()`: `HandTracker(config.model)` and `cv2.namedWindow(...)` are created before the `try/finally` that releases resources, so an exception there leaks the camera. Restructure so that once `cap` is opened, every later failure still runs `cap.release()` and `cv2.destroyAllWindows()`, and `tracker.close()` runs only if the tracker was created. No behaviour change otherwise (same exit codes, same messages).
2. `tests/test_app.py` — strengthen existing tests (keep them camera- and window-free):
   - recording tests: pass a spy recorder (subclass of `tmpmask.capture.Recorder` writing into `tmp_path`, recording every frame given to `write`) and assert none of the written frames has red `(0, 0, 255)` pixels in the recording-dot area (top-right corner), while frames given to `show` during recording do;
   - `test_run_recording_auto_finalized_on_exit`: additionally assert `recorder.is_recording is False` after `run` returns;
   - screenshot taken while recording: the saved PNG (read back with `cv2.imread`) has no red dot pixels;
   - `test_run_key_navigation_and_quit`: after `n` then `p`, assert the message for the purple filter name (`filter_name("purple")` via `tmpmask.texts`) was printed.
