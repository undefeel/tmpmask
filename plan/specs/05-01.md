# 05-01: Sabertooth asset and perspective overlay module

## Target
Source image `assets/source/sabertooth.png` (640x640, 3-channel RGB PNG, no alpha): pure white background (255,255,255) in the corners, a light-gray rounded square (~238,238,238) around a black circle that contains a cartoon sabertooth emblem. The emblem itself contains light colours too (cream fur, white fangs) but they are all enclosed by the black circle.
New module `tmpmask/overlay.py`. Existing `tmpmask/portal.py` defines `Quad = tuple[Point, Point, Point, Point]` in order (top-left, top-right, bottom-right, bottom-left) = (left index tip, right index tip, right thumb tip, left thumb tip) — read it, do not change it.

## Change
1. `tools/make_sabertooth.py` — a script run once by you (and re-runnable): reads the source, builds an alpha mask that removes the outer white background and the gray rounded square, keeps the black circle and everything inside it; crops to the bounding box of the opaque area (so the circle touches the image edges); writes 4-channel BGRA `tmpmask/assets/sabertooth.png`. Suggested method: flood fill from the four corners over "light" pixels (all channels ≥ 200, use `cv2.floodFill` with suitable tolerances or a connected-components approach) → background mask; alpha = 0 on background, 255 elsewhere; soften the edge with a small blur of the alpha (≤ 2 px). Interior light pixels (fangs, fur) must stay opaque. Usage: `.venv/bin/python tools/make_sabertooth.py` (paths resolved relative to the repo root).
2. Run the script and commit the generated `tmpmask/assets/sabertooth.png`.
3. `pyproject.toml`: add `assets/*.png` to `[tool.setuptools.package-data] tmpmask` (keep `*.toml`).
4. `tmpmask/overlay.py`:
   ```python
   ASSETS_DIR: Path  # tmpmask/assets, resolved relative to this file

   def load_rgba(path: Path | str) -> np.ndarray: ...
       # cv2.imread(..., IMREAD_UNCHANGED); 3-channel input gets alpha 255; FileNotFoundError if missing

   def render_overlay(frame: np.ndarray, quad: Quad, image_rgba: np.ndarray,
                      opacity: float = 1.0, outline: bool = True) -> np.ndarray: ...
   ```
   `render_overlay` returns a new frame (input not mutated): perspective-warp `image_rgba` so its corners (0,0), (w,0), (w,h), (0,h) map to the quad points in order (`cv2.getPerspectiveTransform` + `cv2.warpPerspective`, output size = frame size, `INTER_LINEAR`, border transparent). Per-pixel blend: `a = alpha/255 * clamp(opacity, 0, 1)`; `out = frame*(1-a) + warped_bgr*a`. Pixels outside the quad are untouched. If `outline` and opacity > 0, draw the closed quad like `portal.render_portal` does (white, thickness 1, `LINE_AA`). Degenerate quads (area < 4 px², collinear, all equal) or a `cv2.error` from the transform → return a copy of the frame without raising; self-intersecting quads must not raise.

`tests/test_overlay.py` covers: shipped asset loads as HxWx4 uint8; its four corner pixels have alpha 0; its centre pixel has alpha 255; a pixel on a fang/fur area inside the circle (pick one in the asset) is opaque; `load_rgba` on a 3-channel image adds alpha 255; missing file → `FileNotFoundError`; `render_overlay` with a solid red opaque 10x10 image on a 100x100 square quad and opacity 1.0 makes the quad centre red and leaves an outside pixel unchanged (`outline=False`); opacity 0.6 gives the expected mix (±2); a transparent image (alpha 0) leaves the frame unchanged; degenerate and bow-tie quads do not raise; input frame is not mutated.
